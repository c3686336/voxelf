* Running

Run with the supplied =res/envmap.hdr= environment:

#+begin_src sh
cargo run --release
#+end_src

Override it by passing another Radiance HDR equirectangular environment map as
the first argument:

#+begin_src sh
cargo run --release -- path/to/environment.hdr
#+end_src

The default reference renderer estimates linear, scene-referred radiance
from the HDR environment using cosine-weighted Monte Carlo hemisphere samples,
shadow rays, and the metallic-roughness GGX BRDF. The GUI selects this renderer
or an albedo debug view and controls samples per pixel and material. Sampling
uses a fixed seed per pixel; increasing the sample count reduces noise. This is
single-bounce environment lighting, not indirect global illumination. The
interactive display uses Reinhard tone mapping and sRGB encoding.

Traversal uses an eight-entry stack and treats overflow as a miss; the supplied
depth-7 scene fits that limit.

* Capturing a frame

Run a single frame, save linear radiance as Radiance RGBE HDR, and exit:

#+begin_src sh
cargo run --release -- --capture /tmp/voxelf.hdr --renderer reference --samples 128
#+end_src

The HDR capture renders to an offscreen RGBA16F image without tone mapping,
sRGB encoding, or the GUI; RGBE output adds its own quantization. Use a =.png=
output path instead for a tone-mapped, display-encoded 8-bit preview.
=--renderer= accepts =reference= or =albedo=; =--samples= accepts 1–1024.
An optional HDR environment path may be supplied as above. Capture uses a fixed
sampling seed and requests a 640×480 physical window; the output contains the
actual extent, which the window manager may override. Capture requires a window
system. PNG capture also requires swapchain transfer-source support. Pixel-exact
results can vary across GPU drivers.

* SVoDAG

The host builds and edits the scene; host and shader use the same nine-word
node layout and =SvodagView=. Look toward the scene and press =Z= to remove the
first voxel under the center of the view, or =X= to add the adjacent voxel. If
the ray misses the scene, =X= adds at the last voxel inside the scene bounds.

Edits produce persistent roots; they do not update older roots. Before reclaiming
nodes with =Svodag::collect=, pass every root that must remain usable. Roots
omitted from a collection become invalid and their slots may be reused.

The renderer uploads changed slot ranges before drawing with the new root. When
the GPU buffer is too small, it is replaced with a larger buffer and the scene is
uploaded again. Rendering currently waits for each frame to finish, so edits,
collection, buffer writes and replacement occur with no GPU frame in flight.
The application runs a synchronous collection after every 128 effective edits;
large scenes may pause while it traces the retained roots.
