* Running

The host uses =wgpu= for device selection, presentation, scene uploads and
headless readback, with =egui-wgpu= for the GUI. A surface-compatible adapter is
selected when the window is created; headless captures do not create a surface.

Shaders remain Rust: =rust-gpu= =v0.11.0= compiles them through
=spirv-unknown-naga-wgsl=, then wgpu loads the generated WGSL. This is the WGSL
target introduced in =0.10.0-alpha.1=, not a handwritten shader port or Vulkan
SPIR-V passthrough. See the upstream
[[https://github.com/Rust-GPU/rust-gpu/blob/v0.11.0/CHANGELOG.md][rust-gpu changelog]].
=rust-toolchain.toml= pins the matching =nightly-2026-08-15= compiler and required
components; the first build compiles the shader toolchain. Texture and sampler
bindings are separate, render parameters use a uniform buffer, and traversal
bit operations use 32-bit integers for WGSL compatibility. The lighting estimator
and serialized scene layout are unchanged by the backend migration.
Host settings and shader uniforms share the same =RendererMode= enum.
=#[repr(u32)]= fixes its representation; =NoUninit= permits uploads without
requiring every bit pattern to be a valid enum variant.

The GUI reports GPU draw timing when the adapter supports timestamp queries.
Set =WGPU_BACKEND=vulkan= or =WGPU_BACKEND=gl= to select a native backend
explicitly when diagnosing adapter or presentation support.

Run the interactive window with the supplied =res/envmap.hdr= environment:

#+begin_src sh
cargo run --release
#+end_src

There is no command-line parser. The window and validation capture are separate
executables; configure the environment in their source or through the library API.

The default reference renderer estimates linear, scene-referred radiance
from the HDR environment using cosine-weighted Monte Carlo hemisphere samples,
shadow rays, and the metallic-roughness GGX BRDF. The GUI selects this renderer
or an albedo debug view and controls samples per pixel and material. The window
advances a wrapping seed after each completed frame; increasing the sample count
reduces per-frame noise. There is no temporal accumulation yet. This is
single-bounce environment lighting, not indirect global illumination. The
interactive display uses Reinhard tone mapping and sRGB encoding.

Sampling uses =shader::rng::sample_2d= with
[[https://github.com/DEShawResearch/random123][Random123's Threefry2x32-20]].
The integer pixel coordinates form the key; =(sample_index, frame_seed)= is the
counter. Each pair of uniforms is directly addressable, independent of sample
count and call order, so replay does not require advancing mutable RNG state.
The noise sequence differs from the former stateful hash RNG.

Traversal uses an eight-entry stack and treats overflow as a miss; the supplied
depth-7 scene fits that limit.
Face-normal selection uses masks, with X then Y then Z priority for edge and
corner ties; rays starting inside a voxel use the outward exit-face normal.

* Validation captures

Run the headless validation recipe in =host/src/bin/capture.rs=:

#+begin_src sh
cargo run --release --bin capture
#+end_src

This writes =reference.exr= at exactly 640×480, averaging 64 frames with 16
samples per pixel per frame. Edit the recipe's constants and =RenderSettings=
for another capture. No window system, swapchain, presentation, or GUI is used.
Capture and interactive rendering share scene resources and the raymarch pass,
not their rendering loops.

Captures contain top-to-bottom, row-major linear RGB radiance. The wgpu backend
uses one RGBA32F offscreen target and a reusable, row-aligned readback buffer.
Frames use deterministic seeds =seed + frame_index= (wrapping at =u32::MAX=), and are averaged
in linear space with f64 sums before conversion to f32. Repeating identical
settings and seeds is deterministic on the same device; pixel-exact results can
vary across GPU drivers. Frame count must be nonzero; samples per pixel must be
within 1–1024.

Storage has one format: lossless RGB32F OpenEXR, without tone mapping, sRGB
encoding, or half-float/RGBE quantization. =RadianceImage::save= and =load= always
use OpenEXR regardless of the filename extension; use =.exr= for image viewers.
Inspect it with an EXR-capable viewer (for example Krita or ImageMagick). Viewer
exposure/display transforms do not alter the saved radiance. The environment
input may still be a Radiance HDR file.

Tests can call the library directly without launching either executable:

#+begin_src rust
use voxelf::{
    capture::{capture, RadianceImage},
    render::RenderSettings,
    svodag::get_example_svodag,
    gpu::WgpuCapture,
};

let (scene, root) = get_example_svodag(7);
// None selects the small generated environment; pass Some(path) for an HDR map.
let mut backend = WgpuCapture::new(
    scene.data(), scene.depth, root, None, [320, 240],
    RenderSettings { samples_per_pixel: 32, ..Default::default() },
)?;
let image = capture(&mut backend, 128, 0)?;
image.save("reference.exr")?;
let loaded = RadianceImage::load("reference.exr")?;
// loaded.extent() and loaded.pixels() expose linear RGB values for comparisons.
#+end_src

To add another backend, implement =capture::CaptureBackend=: report a fixed
extent and fill the supplied RGB pixel slice for each frame seed. The shared
capture routine handles averaging and storage; no wgpu or window types are
part of that trait. Camera, renderer mode, and linear material parameters live
in =render=; =RenderSettings= fixes them for a =WgpuCapture= instance.

* SVoDAG

The host builds and edits the scene; host and shader use the same nine-word
node layout and =SvodagView=. Look toward the scene and press =Z= to remove the
first voxel under the center of the view, or =X= to add the adjacent voxel. If
the ray misses the scene, =X= adds at the last voxel inside the scene bounds.

Edits produce persistent roots; they do not update older roots. Before reclaiming
nodes with =Svodag::collect=, pass every root that must remain usable. Roots
omitted from a collection become invalid and their slots may be reused.

The renderer uploads changed slot ranges before drawing with the new root. When
the GPU buffer is too small, it is replaced with a larger buffer and the scene is
uploaded again. Rendering currently waits for each frame to finish, so edits,
collection, buffer writes and replacement occur with no GPU frame in flight.
=Queue::write_buffer= stages uploads on the CPU; the next =Queue::submit=
executes the transfers before the frame's draw commands.
The application runs a synchronous collection after every 128 effective edits;
large scenes may pause while it traces the retained roots.
